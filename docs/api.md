# API Reference

All endpoints live under `/api/` and speak JSON. Routes are generated by
DRF's `DefaultRouter`, so each resource exposes the standard list / retrieve
/ create / update / destroy actions unless noted.

**Every endpoint except token issuing requires authentication.**

## Authentication

JWT via `djangorestframework-simplejwt`.

| Method | Endpoint | Body | Returns |
|---|---|---|---|
| `POST` | `/api/auth/token/` | `username`, `password` | `access`, `refresh` |
| `POST` | `/api/auth/token/refresh/` | `refresh` | `access` |

Send the access token on every subsequent request:

```http
Authorization: Bearer <access>
```

## Users and profiles

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/api/users/` | List users |
| `GET` | `/api/users/{id}/` | Retrieve a user |
| `GET` | `/api/users/profiles/` | List profiles |
| `GET`/`PATCH` | `/api/users/profiles/{id}/` | Read or update a profile (bio, avatar) |

The `User` model extends `AbstractUser` with a **unique e-mail**. `Profile`
is a separate `OneToOne` entity, created explicitly — the project
deliberately avoids signals (see [decisions.md](decisions.md)).

## Posts

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/api/posts/` | Feed / post list |
| `POST` | `/api/posts/` | Create a post (author taken from the token) |
| `GET` | `/api/posts/{id}/` | Retrieve a post |
| `PUT`/`PATCH` | `/api/posts/{id}/` | Update — **author only** |
| `DELETE` | `/api/posts/{id}/` | Delete — **author only** |
| `GET` | `/api/posts/{id}/comments/` | List the post's comments |
| `POST` | `/api/posts/{id}/comments/` | Add a comment |

`POST /api/posts/` accepts the post text plus its media items in one
request; media is persisted as separate `PostMedia` rows.

## Post media

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/api/posts/media/` | List media |
| `POST` | `/api/posts/media/` | Upload a media item (`multipart/form-data`) |
| `DELETE` | `/api/posts/media/{id}/` | Remove a media item |

Media rules enforced by the model:

- `media_type` is `image` or `video`;
- `order` is explicit and **unique per post**
  (`UniqueConstraint(post, order)`) — the client controls the carousel
  order, and the database refuses duplicates;
- files are never embedded in `Post` itself.

## Reactions

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/api/reactions/` | List reactions |
| `POST` | `/api/reactions/` | React to a post |
| `PATCH` | `/api/reactions/{id}/` | Change the reaction type |
| `DELETE` | `/api/reactions/{id}/` | Remove the reaction |

Types: `like`, `love`, `haha`, `wow`, `sad`, `angry`.

**One reaction per user per post**, enforced at the database level by
`UniqueConstraint(user, post)` — changing your mind is an update, not a
second row.

## Domain constraints worth knowing

These are enforced by the database, not just by serializers:

| Constraint | Model | Meaning |
|---|---|---|
| `unique_follow` | `Follow` | A user cannot follow the same person twice |
| `no_self_follow` | `Follow` | `CheckConstraint` — you cannot follow yourself |
| `unique_media_order` | `PostMedia` | No two media items share a slot in a post |
| `unique_reaction_per_user_post` | `Reaction` | One reaction per user per post |

## Media and static files

In `DEBUG` mode Django serves `/media/` and `/static/` directly. In
production these must be served by the web server or object storage.
